# 2 GDPR

## 2.1 GDPR

### 说明

<div style="padding-left:2em"><span style="color:red">批注1</span>：【GDPR】<br>1. GDPR流程整体改为异步，应用启动的时候从后台获取数据。GDPR获取数据回来的时候，如果还在开屏阶段，未进入主页，则等待进入主页的时候再弹出（避免和开屏动画及开屏广告冲突）。<br>2. 如果已经结束了开屏阶段，则GDPR立即弹出。此时正在展示插屏广告的话，则弹出的界面在插屏广告之下，用户手动关闭插屏广告之后即可操作<br>3. 对于不支持GDPR的国家，因为已经改成异步，因此从GDPR后台数据可以判定不支持，不会弹出对话框，也不会增加等待时间，因此用户无感。不用特殊处理</div>

## 5.5 native广告 — 5

### 页面布局

<img src=".exports/v1.1.0/05-native广告/images/005-native广告-—-5-sslnmwwwVTCSUVHOU8U5cC-diagram-5.png" width="180" />

### 说明

<div style="padding-left:2em"><span style="color:red">批注1</span>：【native广告逻辑汇总】<br>搜索设备页面、教程页面：ca-app-pub-3925850724927301/4645698342<br>退出APP的底部浮层native：ca-app-pub-3925850724927301/7415164047<br>「界面」<br>1. 加载中的加载框（横屏）+广告标识<br>2. 横版+竖版UI<br>3. native广告位置：搜索设备页面底部、教程页面底部、退出APP时的底部浮层<br>「逻辑」<br>1. 加载规则：用户trigger了有native广告位的页面，才开始加载native广告，加载成功后，则展示native广告<br>1.1 消耗一个native广告后，用户再次trigger一个有native广告位置的页面后，才开始加载新的native广告<br>1.2 如果用户在有native广告的页面停留，超过30s后，开始加载下一个广告，在下一个广告加载成功之前，仍然展示原广告<br>1.3 如果在下一个native广告还没有预加载成功时，用户就已经trigger到下一个有native广告的页面了，该页面需要展示加载框，并继续加载广告<br>1.4 加载前先检查是否有上次加载成功但未展示的广告，有的话先展示上次的广告，不同位置的缓存也可用<br>2. 加载失败策略：<br>加载失败后，间隔3s再次尝试加载<br>2.1 请求连续加载失败4次，计为1个失败，间隔30s之后继续主动加载<br>2.2 若加载1个广告失败后，间隔计时还未到30s，用户就trigger了下一个有native广告的页面，则立马加载下一个native广告（就是说30s、3s计时会被用户的trigger打断，trigger的层级高于30s、3s的间隔计时）(trigger后4次request不用重新计数)<br>2.3 连续4个native广告都加载失败，本次启动app都不再加载（native的加载框也不再展示）<br>2.4 针对退出APP的底部浮层广告<br>*退出APP的底部浮层广告最多只有4次加载失败的机会<br>* 如果用户触发了退出APP的底部浮层广告，一直停留，如果失败了四次，则停留在加载状态<br>3. 无网络状态，不加载广告<br>4. 这三个位置的native广告都偏好加载横屏广告<br>5. 【新增】如果在某一个位置native已经展示了15s（&lt;30s）时，将软件退到后台，则计时器会停止，并且回到软件回到前台，也无法继续计时（开发难度大）</div>
